Tailwind IntelliSense in Elm: A NeoVim Recipe

2025-07-04 #elm #neovim #tailwind #lsp #recipe

If you’re using Elm with Tailwind CSS in NeoVim, you’ve probably noticed that IntelliSense doesn’t work out of the box. Here’s a quick recipe to fix that.

The Problem

Tailwind’s LSP doesn’t recognize Elm’s syntax for CSS classes. When you write:

1div [ class "bg-blue-500 text-white p-4" ] [ text "Hello" ]

You get no autocomplete, no validation, and no hover documentation for your Tailwind classes.

The Solution

My Setup (LazyVim)

Here’s what works for me using LazyVim. If you’re using a different NeoVim distribution, your mileage may vary:

 1{
 2  "neovim/nvim-lspconfig",
 3  opts = {
 4    servers = {
 5      tailwindcss = {
 6        filetypes_include = { "elm" },
 7        -- exclude a filetype from the default_config
 8        filetypes_exclude = {},
 9      },
10    },
11    setup = {
12      tailwindcss = function(_, opts)
13        local tw = LazyVim.lsp.get_raw_config("tailwindcss")
14        opts.filetypes = opts.filetypes or {}
15
16        -- Add default filetypes
17        vim.list_extend(opts.filetypes, tw.default_config.filetypes)
18
19        -- Remove excluded filetypes
20        opts.filetypes = vim.tbl_filter(function(ft)
21          return not vim.tbl_contains(opts.filetypes_exclude or {}, ft)
22        end, opts.filetypes)
23
24        opts.settings = {
25          tailwindCSS = {
26            includeLanguages = {
27              elm = "html",
28            },
29            experimental = {
30              classRegex = {
31                { [[\bclass[\s(<|]+"([^"]*)"]] },
32                { [[\bclass[\s(]+"[^"]*"\s+"([^"]*)"]] },
33                { [[\bclass[\s<|]+"[^"]*"\s*\+{2}\s*" ([^"]*)"]] },
34                { [[\bclass[\s<|]+"[^"]*"\s*\+{2}\s*" [^"]*"\s*\+{2}\s*" ([^"]*)"]] },
35                { [[\bclass[\s<|]+"[^"]*"\s*\+{2}\s*" [^"]*"\s*\+{2}\s*" [^"]*"\s*\+{2}\s*" ([^"]*)"]] },
36                { [[\bclassList[\s\[\(]+"([^"]*)"]] },
37                { [[\bclassList[\s\[\(]+"[^"]*",\s[^\)]+\)[\s\[\(,]+"([^"]*)"]] },
38                { [[\bclassList[\s\[\(]+"[^"]*",\s[^\)]+\)[\s\[\(,]+"[^"]*",\s[^\)]+\)[\s\[\(,]+"([^"]*)"]] },
39              },
40            },
41          },
42        }
43
44        -- Add additional filetypes
45        vim.list_extend(opts.filetypes, opts.filetypes_include or {})
46      end,
47    },
48  },
49}

For Vanilla NeoVim

If you’re using plain nvim-lspconfig, I’m guessing you’d need something like this (but I’m mostly spitballing here - you get the idea):

 1require('lspconfig').tailwindcss.setup({
 2  filetypes = {
 3    'html', 'css', 'javascript', 'typescript', 'react', 'vue', 'svelte', 'elm'
 4  },
 5  settings = {
 6    tailwindCSS = {
 7      includeLanguages = {
 8        elm = "html",
 9      },
10      experimental = {
11        classRegex = {
12          { [[\bclass[\s(<|]+"([^"]*)"]] },
13          { [[\bclass[\s(]+"[^"]*"\s+"([^"]*)"]] },
14          { [[\bclass[\s<|]+"[^"]*"\s*\+{2}\s*" ([^"]*)"]] },
15          { [[\bclass[\s<|]+"[^"]*"\s*\+{2}\s*" [^"]*"\s*\+{2}\s*" ([^"]*)"]] },
16          { [[\bclass[\s<|]+"[^"]*"\s*\+{2}\s*" [^"]*"\s*\+{2}\s*" [^"]*"\s*\+{2}\s*" ([^"]*)"]] },
17          { [[\bclassList[\s\[\(]+"([^"]*)"]] },
18          { [[\bclassList[\s\[\(]+"[^"]*",\s[^\)]+\)[\s\[\(,]+"([^"]*)"]] },
19          { [[\bclassList[\s\[\(]+"[^"]*",\s[^\)]+\)[\s\[\(,]+"[^"]*",\s[^\)]+\)[\s\[\(,]+"([^"]*)"]] },
20        },
21      },
22    },
23  },
24})

What’s Happening

Both configs do the same thing with different syntax:

  1. Add elm to filetypes - Tells Tailwind LSP to activate for Elm files
  2. includeLanguages = { elm = "html" } - Treats Elm syntax like HTML for class detection
  3. classRegex patterns - Regular expressions that match Elm’s various class syntax patterns:
    • class "bg-blue-500" - Basic class attribute
    • class "text-lg" ++ " font-bold" - String concatenation
    • classList [ ("active", isActive) ] - Conditional classes

The Result

Now you get full Tailwind IntelliSense in your Elm files:

  • Autocomplete for class names
  • Hover documentation
  • Color previews
  • Validation warnings for invalid classes

Full Setup

My complete NeoVim config (including this setup) is available at github.com/cekrem/dotfiles if you want to see how it fits into a larger LazyVim configuration.

This small addition makes Elm + Tailwind development much more pleasant. No more guessing at class names or checking the docs constantly.
